# D-20260811-021：任务书执行原则固化（scope 强制 / 失败限制 / checkpoint 回滚）

> 状态：已确认｜确认者：用户｜时间：2026-08-11T10:40:00Z

## 通俗解释

开发原则里"改动范围只写不查、失败没有次数上限、失败后不会自动退回上一个好版本"这三条，这次全部变成程序强制规则：

1. **越界就拒绝**：任务交接时，凡是改到任务书没声明的文件，一律拒绝交接并列出越界文件。
2. **失败有上限**：每个任务书可规定最多失败几次、最多改几个文件；连续失败超限就"判死刑"（blocked），不再原地无限重试。
3. **自动退回**：任务开始时记下好版本（checkpoint），验证/测试失败时自动把任务分支退回最近的好版本并作废旧结果，从那里重来；主线 main 不受影响。

同时明确最终状态三选一：PASS（通过，可合并）、BLOCKED（等设计决策）、FAIL（停止并保存现场）。

## 正式表述

1. 任务书 schema v2：`limits`（max_retries/max_files/max_same_error）、`revert_on_fail`、`checkpoint_policy`。
2. handoff 强制 `changed_files ⊆ 任务书 outputs`；语义级 scope 随阶段 1 联动。
3. 失败计数：`failure_count`/`checkpoint_commit` 进任务生命周期字段；超 max_retries 置 blocked；max_same_error = 阶段级连续失败计数。
4. 自动回滚：checkpoint 默认 base_commit，通过后推进为 head；失败且 revert_on_fail 时 reset 分支 + 代数+1 + 重开租约；main 不受影响。
5. 状态语义：PASS=ready_to_merge、BLOCKED=decision_required、FAIL=blocked。
6. v1 任务书文档必须升级 v2 并补齐 limits（缺省 max_retries=3）。
