# D-20260811-012：历史补登豁免机制(A) + Windows CI(加) + MCP 越权暂缓

> 状态：已确认｜确认者：用户｜时间：2026-08-11T08:38:09Z

## 通俗解释

三件事一起拍板：

1. **老账补办证明（A）**：以前 5 个改动没按现在的新规矩附"决策批准书"，而旧提交又不能改。现在给它们各开一张"官方补办证明"（写清是哪个提交、为什么），电脑校验认这张证明就放行，不用去改历史。这样以后做全量复查也不会再无端报错。
2. **Windows 也自动体检（加）**：以前自动检查只在 Linux 上跑，Windows 特有的毛病（斜杠、编码）要靠人工才发现。现在让 GitHub 在 Windows 上也自动跑一遍测试和校验，双平台都绿才算过。
3. **越权漏洞先记着（暂缓）**：某些外挂工具能绕过子任务的写入限制，这个漏洞按上次的决定继续先不修，风险保持公开可见。

## 正式表述

1. **V2=A**：`schemas/decision.schema.json` 新增可选顶层字段 `historical_backfill`（数组，每项含 40 位 `commit` SHA 与 `reason`）。`scripts/workflow.py` 的 `validate_commit_rules` 在遍历提交区间时，对出现于任一已确认决策 `historical_backfill` 列表的 commit 豁免"同 commit 决策 JSON / 00 卷同步"逐 commit 规则；豁免声明本身受核心文件门禁与用户确认保护，实现可全量重放校验且不改写 Git 历史。
2. **F4=加**：`.github/workflows/workflow-integrity.yml` 增加 `strategy.matrix.os = [ubuntu-latest, windows-latest]`（`fail-fast: false`），两平台并行执行单元测试、全库校验与提交区间校验。
3. **V1=暂缓**：MCP 文件写工具以工具名为权限键绕过 `.opencode/agent/*.md` 的 `edit: {"*": deny}` 边界的漏洞，延续 `D-20260811-010` 暂缓，不在本轮修复，风险保持开放。
