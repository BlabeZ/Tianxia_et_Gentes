# D-20260814-002：T-048 Gate 0 拍板——用户目录写入边界与 ASCII mod 测试路径

> 状态：已确认｜确认者：user｜时间：2026-08-14

## 通俗解释

T-048 是机器 A 上跑真实游戏加载测试的前置任务。它被两道"能不能动手"的门卡住，本次已拍板放行：

1. **游戏写日志问题**：自动启动 HOI4 时，游戏自己会往你的"我的文档/Paradox Interactive"里写日志和缓存，这跟"agent 不得碰用户目录"的规矩冲突。拍板结果：**受控例外**——先实测摸清游戏会写哪些路径、形成白名单，只在白名单内放行；测试前后对用户目录做完整快照比对，白名单外出现任何写入都判测试失败。你的日志和设置文件 agent 只读，绝不修改。
2. **中文路径问题**：仓库路径含中文，HOI4 对这种路径加载 mod 不可靠。拍板结果：在机器 A 上**预建一个纯英文路径的 junction（快捷方式）指向仓库 mod/ 文件夹**，游戏读的是同一份文件，仓库更新后永远一致，无需同步。

还有第三道门（真实启动标志的机器 A 人工侦察）不属于本次拍板，等你在机器 A 上人工跑一次游戏、提交脱敏证据后再审查。

## 正式表述

- 门禁 A：`user_docs_path` 维持只读，但执行器按 Gate 0 实测结果维护路径级 allowlist；测试会话内允许其启动的 HOI4 进程在 allowlist 内写入；执行前后对用户目录做递归快照（相对路径/类型/大小/mtime），allowlist 外写入即阻断 PASS 并判 INCONCLUSIVE；执行器只读日志增量。
- 门禁 B：机器 A 预建只读 ASCII 绝对路径指向仓库 `mod/` 的 junction/symlink（Windows junction 无需管理员权限）；执行器仅验证存在性与内容树指纹，不创建、不更新外部映射；ASCII 校验覆盖 descriptor 的 `path`/`archive` 等间接引用。
- 门禁 C：机器 A 人工基线侦察证据（argv、mod-loaded、readiness/fatal 标志）缺失前，T-048 保持 `decision_required`。
