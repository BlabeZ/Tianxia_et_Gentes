# D-20260811-009：AI 工作流硬约束纵深加固

> 状态：已确认｜确认者：用户｜时间：2026-08-11T07:03:00Z

## 正式表述

远端 main 保护是最终强制层；本地 Git hooks 是快速反馈层。设定层待定语义的消失必须由同一提交内的结构化 `resolved_pending` 记录逐项授权，统一校验器同时支持提交区间和 Git index 检查。

入库 hooks 使用跨平台 Python 入口。pre-commit 检查暂存区的同提交义务并运行标准库单元测试；pre-push 从 Git hook stdin 获取远端与本地 SHA，分别传入 `--base` 和 `--head`。

本阶段不增加 OpenCode plugin。它仅覆盖单一工具，且字符串路径拦截不能替代操作系统只读边界、固定导出器和远端仓库保护。

## 通俗解释

AI 删除“待定”字样时，不能再靠一份泛泛的决策文件蒙混过关：系统会要求它指出删的是哪一行、用户批准了什么。提交前本机会尽早提醒，真正决定 main 能否合并的仍是 GitHub 远端规则。

## 实施门禁

- 逐提交核对待定标记的净减少量，并以原行规范化文本的 SHA-256 作为稳定证据。
- `resolved_pending` 必须精确匹配文件路径和行指纹；同一指纹多次消失时必须声明足够的 `occurrences`。
- `validate --staged` 读取 Git index，不以未暂存工作区内容代替即将形成的提交。
- hooks 的启用状态必须写入机器就绪清单，并明确可被 `--no-verify` 绕过。
- 未能核实 GitHub ruleset 时，不得宣称 CI 已不可绕过。

实现采用两级抵消：同一 diff hunk 内新增的任一待定标记可抵消一个被删标记，用于识别“改写但仍待定”；跨 hunk 只抵消规范化原行完全相同的搬迁。抵消后剩余的每个标记出现次数都必须由 `resolved_pending` 授权。
