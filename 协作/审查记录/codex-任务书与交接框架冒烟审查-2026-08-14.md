## 已确认缺陷

### H1：生命周期提交失败并非原子回滚

真实执行 T-049 `task complete` 时，提交钩子因测试 fixture 依赖活动任务书而失败。命令返回错误后，任务书移动、`tasks.json` 与台账仍保留在暂存/修改状态；需要人工撤销。这直接证明 `complete` 的“原子提交”失败路径不成立。

源码上，`commit_scoped_changes` 在 `git add`、范围检查或 `git commit` 失败时只抛错，不恢复 index/worktree；`assign`、`handoff`、`validation-result`、`complete`、`checkpoint` 均在调用前修改文件，且没有统一事务回滚。只有 `test-result` 单独保存原文并在失败时恢复，其回滚测试不能覆盖其他生命周期命令。

影响：一次 hook、权限、磁盘或 Git 错误即可留下“内存认为失败、磁盘看似已转态”的半完成现场；后续主代理可能误提交错误状态或被干净工作区门禁永久阻塞。

### H1：heartbeat/reclaim 可在任意分支直接改权威状态且不提交

隔离临时 clone 的真实冒烟中，在 `smoke/non-main` 分支运行：

1. `task heartbeat --id T-043 --generation 1` 成功；
2. `task reclaim-stale --now 2100-01-01T00:00:00Z` 成功；
3. 两条命令都直接改写 `协作/tasks.json` 与派生台账，只留下未提交工作区改动。

两函数没有 `lifecycle_preflight`、main 分支检查或 `commit_task_state`。运行时锁只能避免同时执行，不能保证主分支、主代理或持久化原子性。这与“状态持久化、不信对话记忆”和“单一主调度器”契约冲突。

### H1：验证/加载测试前的 raw Git 合并没有硬门禁

当前活证据是 T-043：状态为 `pending_test`，但交付 head 已进入本地和远端 main。`validate` 只要求待测试任务有 handoff/head/report 且无活动租约，不检查 head 是否已被提前合并；pre-commit/pre-push 也未检查“将进入 main 的任务 head 必须 ready_to_merge”。

影响：主代理只要直接运行 `git merge`，就能把未验证或未加载测试内容送入 main；之后即使状态机拒绝 `complete`，风险代码已经成为主线内容。当前 T-043 正处于这种状态。

## 中高风险缺口

### H2：任务提交引用只校验格式，不校验对象和祖先关系

`tasks.schema.json` 只要求 40 位十六进制；`validate_tasks` 只在活动阶段做字段存在检查，没有统一执行 `git cat-file -e` 与 `merge-base --is-ancestor`。T-004 的错误完整 SHA 因而长期通过所有门禁。历史审计、回归定位和交接真实性会受损。

建议对非 `legacy` 任务按状态校验 base/head/checkpoint：对象必须存在、head/checkpoint 必须位于合法祖先链、done 的 head 必须已进 main。历史债务应通过显式 legacy/migration 清单豁免，不应静默忽略。

### H2：静态验证报告没有结构化绑定和防重放

`validation-result` 对普通验证报告只检查“路径位于 `协作/审查记录/` 且文件存在”，没有 schema，也不绑定 task、generation、base/head、验证命令、验证机器或内容哈希；任意旧 Markdown 理论上可被重复用于登记 PASS。加载测试报告已有严格绑定和 `consumed_by`，静态验证尚未达到同等完整性。

### H2：跨机同步状态没有形成闭环

本地 `main` 当前领先 `origin/main` 9 个提交；`git pull --ff-only` 仍只输出“已经是最新的”，因为它不提示本地未发布提交。开工协议没有强制检查 ahead/behind，任务完成命令也按设计不推送。另一台机器此时会读取旧版工作流和旧任务状态。

建议在跨机分配、交接和测试前强制 `git rev-list --left-right --count origin/main...main == 0 0`，将“本地领先但未发布”视为同步未完成。远端 main ruleset 本轮因 GitHub API 匿名速率限制返回 403，保护状态无法确认，不能宣称远端门禁不可绕过。

## 中低风险与设计债务

1. **权限冒烟入口含糊**：`opencode run --agent execute|verify` 对 subagent 会回退默认主代理并产生假阳性；README 应明确必须由 primary agent 使用 `task` 工具启动目标 subagent，并把 fallback 文本视为测试失败。正确入口下本轮权限结果全部符合预期。
2. **外部目录兜底为 ask**：execute/verify 的 `external_directory: *` 是 `ask`，不是 deny。虽然项目规则禁止接触本体，交互时仍可能被人工误批；硬约束更适合默认 deny，再对白名单资源逐项 allow。
3. **加载测试队列表达不完整**：T-043 为 `pending_test` 且 blocker 为空，但当前 `game-test` 在 T-048 Gate 0 完成前只能返回 INCONCLUSIVE；T-043 未在依赖或 blocker 中表达该先决条件，状态看起来可推进，实际没有自动 PASS 路径。
4. **任务元数据漂移**：T-045 任务书已改为“四极 set_politics + 项目党派状态初始化”，registry `module` 仍写“key=坐标表ID”；T-046 已 `stale/g2`，仍保留 g1 的旧 `validation_report`。当前 validator 不检查标题一致性或 stale 状态残留字段，容易误导人工调度。
5. **远端保护未实证**：Actions 只在 PR/main push 后运行；若 GitHub ruleset 未强制 PR 和必需检查，`--no-verify` 仍可绕过本地 hooks。本轮 API 限流，结论为“未知”，不是“已保护”。
