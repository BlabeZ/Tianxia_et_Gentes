# 16-KR中欧同盟投票周期与国策联动（定时会议机制精读）

> 适用：**定时周期性会议/投票系统**（flag 计时 + MTTH 结算 + 结果广播 + 周期重置）、议程对象体系、国策/决议与周期机制的联动。
> 参考样本：Kaiserreich（KR，`E:\Steam\steamapps\workshop\content\394360\1521695605`）中欧同盟（Mitteleuropa）的**定时会议投票**与**国策/决议联动**。
> **姊妹篇**：[15-KR中欧同盟GUI专题.md](15-KR中欧同盟GUI专题.md)（面板 UI 与投资按钮）；本专题聚焦"会议周期如何运转"与"国策/决议如何接入"。

## 一、定时会议投票周期总览（核心机制）

中欧同盟的会议投票是**约 6 个月的固定周期循环**：

```
[启用] events.1000（德国激活中欧）→ GER_enable_mitteleuropa → set MIT_election flag
   │
   ▼
[投票期 ≈178 天] 玩家在 GUI 面板投资 PP 支持议程（可随时改票，30 天冷却）
   │  on_daily_GER 每日重算分数+排序+刷新 GUI
   │  150 天时 events.11 提醒未投票玩家
   │
   ▼
[结算触发] events.0（MTTH 3 天；条件：MIT_election flag 存在 >178 天）
   │  锁定 GUI（MIT_event_chain_ongoing + 全员关面板）
   │  重算分数 → 排序 → 处理领导权挑战 → 前三名+主席议程存为事件目标
   │
   ▼
[决策] events.1（主席国选执行哪个议程；ai_chance 按分数加权）
   │  → MIT_add_agenda_reward（当选议程奖励全圈生效）
   │  → 广播 events.2/3 给成员
   │  （若仅领导权挑战 → events.6/7/8 直接处理）
   │
   ▼
[结算] events.10（隐藏）：解锁 GUI、清空全部投票状态、议程复位、
   │      当选议程入冷却（MIT_lock_agenda）、解锁旧冷却议程、可能换主席
   │      → 重置 GER MIT_election flag（新一轮开始）
   │      → 给每位成员派发 events.11（150 天后提醒）
   ▼
[新周期] 循环
```

**周期长度**：`MIT_election days > 178` 触发结算 + `events.11 days = 150` 提醒 → 投票窗口 ≈ 178 天（约 6 个月）。

## 二、定时机制的精确定时实现

### 1. 周期计时：`MIT_election` flag + `days` 参数（`events/MIT events (Mitteleuropa).txt`）
```pdx
country_event = { #new election boot event
	id = germany_mitteleuropa_events.0
	hidden = yes
	trigger = {
		MIT_is_current_president = yes
		GER = { has_country_flag = { flag = MIT_election days > 178 } }   # ← 计时核心
	}
	mean_time_to_happen = { days = 3 }                                    # MTTH 轮询
	...
}
```
**定时实现**：flag 自带存活天数（`days > 178` 判断）——不用单独计时器变量；MTTH 3 天轮询保证触发不晚于周期 +3 天。

### 2. 周期重置：结算事件末尾
```pdx
#reset election cycle
GER = { set_country_flag = MIT_election }   # events.10 末尾：重新计时
```
（`set_country_flag = X` 无参数即重置 flag 存活天数归零。）

### 3. 投票提醒：提前 150 天
```pdx
# events.10 结算时给每位成员排程提醒
for_each_scope_loop = {
	array = MIT.economic_sphere:members
	...
	country_event = { id = germany_mitteleuropa_events.11 days = 150 }   # 投票提醒
}
```
（`events.11` 按 `has_variable = MIT_supported_agenda` 分"未投票/已投票"两种文案。）

### 4. 结算期间锁定 GUI
```pdx
# events.0
set_global_flag = MIT_event_chain_ongoing        # 全局锁：面板按钮禁用
every_country = { MIT_close_mitteleuropa_panel = yes }
# events.10（结算结束）
clr_global_flag = MIT_event_chain_ongoing        # 解锁
if = { limit = { is_ai = yes } MIT_open_mitteleuropa_panel = yes }
```
（GUI 打开按钮的 triggers 里有 `NOT = { has_global_flag = MIT_event_chain_ongoing }` 禁用。）

## 三、结算链精读（events.0 → 1/6 → 10）

### 1. events.0（选举启动，hidden + MTTH）
1. 锁 GUI（见上）；
2. `MIT_recalculate_all_agenda_scores = yes` + `MIT_resort_agendas_based_on_score = yes`（全议程重算分数并按分数排序）；
3. **领导权挑战处理**：若 `MIT_challenge_leadership` 议程在排序第一 → 其第一支持者存为 `MIT_next_chairman` 事件目标，挑战议程从列表移除，给发起者 365 天 `MIT_leadership_challenge_cooldown`；
4. **前三名存为事件目标**：`MIT_first/second/third_place_agenda`（用 `agenda_supporters^0` 找主要支持者）；
5. **主席议程作为第四候选**：主席当前支持的议程（若不在前三且无 `MIT_qualified_majority_in_effect`）存为 `MIT_chairman_agenda`；
6. 按议程数分流：仅领导权挑战（count=0）→ `events.6`；否则 → `events.1`。

### 2. events.1（议程选举结果——主席国选择）
- desc 按议程数量分 7 种文案（0/1/2/3/4+ 议程，含主席议程变体）；
- **选项 = 1/2/3 名 + 主席议程**，每个选项 `trigger = { has_event_target = MIT_xx_agenda }`；
- **ai_chance 加权**（AI 主席的选择逻辑）：
```pdx
ai_chance = {
	base = event_target:MIT_first_place_agenda.agenda_score          # 分数越高越可能被选
	modifier = { factor = 0  original_tag = GER OR = { ... } }       # 德国必须选主席议程或自己主要支持的
	modifier = { factor = 0  support_comparison < 0.3 }              # 与第一名差距过大的不选（第二名选项）
	modifier = { add = 100  check_variable = { MIT_supported_agenda = event_target:MIT_first_place_agenda } }
}
```
（支持率比较用 `support_comparison = 第二/第一` 比值分级加权 0/0.25/0.5。）
- 选中后：`save_event_target_as = MIT_enacted_agenda` → `MIT_add_agenda_reward`（发奖励）→ 广播 `events.2/3` 给其他成员（非主席国看结果）→ 触发 events.10 结算。

### 3. events.6/7/8（领导权挑战专链）
- `events.6`：主席国接不接受挑战——接受（70）→ `events.7` 新主席就任；拒绝（30，需非合格多数且民主国/大国）→ `MIT_defied_leadership_challenge` 限时 idea（1 年）；
- `events.7`：新主席就任广播（desc 按"自己/他人"分文案），`MIT_set_new_chairman` 换 `MIT` 动态 tag；
- `events.8`：拒绝挑战的后续。

### 4. events.10（结算收尾，hidden）
1. 解锁 GUI；
2. **清空成员投票状态**：`MIT_recent_agenda_change`/`MIT_received_agenda_event`/`MIT_received_leadership_event`/`MIT_agenda_count`/`MIT_agenda_investment`/`MIT_supported_agenda`/`frame@PREV`；
3. `MIT_reset_agendas`（清全部议程的支持者数组/分数/索引 + 清 `global.MIT_sorted_voted_agendas`）；
4. **解锁冷却议程**：遍历 `global.MIT_on_cooldown_agendas` → `MIT_unlock_agenda`；
5. **当选议程入冷却**（无专属效果的议程）→ `MIT_lock_agenda`（加入冷却数组）；
6. **主席更替**：若挑战成功且前主席未拒绝 → `MIT_set_new_chairman` + 挑战议程入冷却；
7. 重置 `GER MIT_election`；
8. 每位成员排 `events.11 days = 150`。

## 四、议程对象体系（议程 = 角色）

### 1. 议程定义（`common/characters/MIT characters.txt`）
每个议程 = **一对角色**（议程本体 + `_name` 变体用于 idea 名）：
```pdx
MIT_generic_industrial_projects = { name = MIT_generic_industrial_projects }   # 议程本体（存支持者/分数/flag）
MIT_generic_industrial_projects_name = { name = MIT_generic_industrial_projects_idea }  # 限时 idea 名来源
```
议程清单：generic 8 个（工业项目/军备/基建/金融救助/工业顾问/军备专家/凝聚力基金/法律改革）+ 改革 10 个（指令体系/协商大会/合格多数/议会批准/监管体系/预算配额/执行总署/扩大总署/共同旅行区/欧洲马克/央行）+ 领导权挑战。

### 2. 注册与解锁（`MIT effects (Mitteleuropa).txt`）
```pdx
MIT_unlock_agenda = {   # 全局解锁（德国改革国策完成时）
	if = { limit = { NOT = { is_in_array = { global.MIT_agendas = var:target_agenda } } }
		add_to_array = { global.MIT_agendas = var:target_agenda }
		... 给所有开着面板的成员 MIT_update_agenda_list }
}
MIT_unlock_agenda_for_country = {   # 国家专属解锁（成员国国策）
	... add_to_array = { global.MIT_agendas = ... } + add_to_array = { target_agenda:available_for = THIS } }
}
MIT_lock_agenda = {   # 入冷却（当选后）
	... 加入 global.MIT_on_cooldown_agendas + 从 global.MIT_agendas 移除 ... }
```
- `available_for` 数组 = 国家专属议程的可见名单；
- 议程奖励动态名：`[AGENDA_IDEA]_idea`（180 天限时 idea）或 `[AGENDA_IDEA]_idea_effect`（专属脚本，见 15 号文档第五节）。

## 五、国策联动（双向接入）

### 1. 议程 → 国策（议程生效解锁国策）
**议程执行时设全局 flag → 国策的 available 读取 flag → 国策完成广播制度 modifier**：
```pdx
# GER_directive_system 国策（GER focus 9847 行）
focus = {
	id = GER_directive_system
	available = {   # ← 议程生效后才能点！
		custom_override_tooltip = { tooltip = GER_directive_system_passed_tt
			has_global_flag = MIT_directive_system_in_effect }   # 议程设定的全局 flag
	}
	completion_reward = {
		MIT_add_directive_system_modifiers = yes      # 德国获得制度 modifier
		every_other_country = {                       # 广播给全体中欧成员
			limit = { GER_is_in_mitteleuropa = yes OR = { is_subject_of = ROOT is_subject = no } }
			country_event = germany_mitteleuropa_events.1002   # 成员同步获得
		}
		...
	}
}
```
制度国策链（GER 树内）：`GER_regulation_system`(9782) / `GER_directive_system`(9847) / `GER_mitteleuropa_court`(9937) / `GER_berlin_bureaucracy`(10032) / `GER_qualified_majority_voting`(10080) / `GER_europamark`(10128) / `GER_enforcement_commission`(10221) / `GER_conference_control`(10275)——**每项 = 一个议程的"落地成文法"**：议程投票通过 → flag 生效 → 国策解锁 → 德国完成 → 全员广播事件获得 modifier/idea（如 `MIT_add_directive_system_modifiers`、`add_ideas = MIT_berlin_bureaucracy`）。

### 2. 国策 → 议程（国策解锁议程 / 强化议程）
- 议程定义文件 `MIT characters.txt` 中 `MIT_improve_generic_agenda_rewards`（effects 文件）：德国完成相关国策后强化通用议程的奖励；
- 成员国角色国策：`AFR_join_mitteleuropa`、`BLR_Increase_Role_In_Mitteleuropa`、`DEN_strengthen_mitteleuropa_ties`（→ `DEN_beyond_mitteleuropa` 退出）、`ARG_Renegotiate_with_Mitteleuropa`——加入/提升在圈内角色的国策，完成时 `GER_add_to_mitteleuropa` 或提升 `MIT_agenda_investment` 权重。

### 3. 加入/退出机制（`GER_add_to_mitteleuropa` / `GER_remove_from_mitteleuropa`）
加入 = 经济圈 `MIT = { add_to_economic_sphere = yes }` + `MIT_mitteleuropa_modifier` 动态修正 + **按德国已完成的制度国策逐项叠加 modifier**（15 号文档第五节 6）。退出/被踢有专门 effect（`GER_leave_mitteleuropa`/`GER_kick_from_mitteleuropa` 供事件用）。

### 2. 中欧相关的其他决议
- `GER_peace_summit_repeatable`（和平峰会，150 天冷却，`available = { second_weltkrieg_has_begun = no }`）——降威胁度用，非 MIT 专属但与圈内外交协同；

## 七、on_actions 每日刷新（`on_actions_Germany.txt` 541-544 行）
```pdx
on_daily_GER = {
	effect = {
		#Update Mitteleuropa GUI
		if = { limit = { MIT_is_active = yes }
			MIT_recalculate_all_agenda_scores = yes    # 全议程重算（支持国 mtth 权重）
			MIT_resort_agendas_based_on_score = yes    # 排序
			MIT_update_gui = yes                       # dirty 重绘
		}
	}
}
```
**关键**：议程分数不是投票时冻结的，而是**每日随支持国实力动态重算**（`mtth:mitteleuropa_agenda_score_calculation` 按支持国工厂/战争状态等加权）——投票截止前分数一直在变，鼓励持续拉票。

## 八、完整时序图（一个完整周期）

```
Day 0    events.1000 启用（德国）：GER_enable_mitteleuropa → MIT_election flag 计时开始
Day 0-178 投票期：玩家 GUI 投资（1/5/10/50 PP）支持议程（30 天冷却）
          on_daily_GER：重算分数/排序/GUI
Day 150   events.11 投票提醒（未投票/已投票双文案）
Day 178+  events.0（MTTH≤3 天）：锁 GUI → 结算准备 → 前三名+主席议程
          → events.1：主席选议程（ai 按分数加权）
             → MIT_add_agenda_reward（奖励全圈）→ 广播 events.2/3
          → events.10：解锁 GUI、清投票状态、议程复位/冷却、可能换主席
             → 重置 MIT_election（新周期）→ 排 events.11（+150 天）
```

## 九、对本项目的借鉴清单

| 中欧周期机制 | 本 mod 对应需求 | 移植要点 |
|---|---|---|
| flag + days 计时 + MTTH 结算 | 任何定期会议/朝贡大会/峰会 | `has_country_flag = { flag = X days > N }` + `mean_time_to_happen` 轮询 |
| 结算链三事件（启动/决策/收尾） | 会议三阶段 | 启动存事件目标 → 决策事件（ai_chance 加权）→ 收尾清状态+重置 |
| 事件目标传参（前三名+主席议程） | 多候选项投票 | `save_event_target_as` + trigger 检测 |
| 议程=角色对象 | 可投票议案库 | characters 一对角色（本体+name 变体）+ global 数组 + 冷却数组 |
| 议程→flag→国策→全员广播 | 议案通过后落地制度 | 双向联动：议程设 flag，国策 available 读 flag，完成广播 modifier |
| 每日动态重算分数 | 支持度实时变化 | on_daily + mtth 加权 + 排序 + dirty |
| 周期锁 GUI | 结算期间防操作 | 全局 flag + 全员关面板 + 按钮禁用 trigger |
| ai_chance 分数加权决策 | AI 参与会议 | base=分数 + 比值分级 modifier + 支持者加成 |
| 冷却机制（议程+挑战） | 防止重复当选 | global.MIT_on_cooldown_agendas + unlock/lock |
