# 01-工程结构与开发流程

> 适用：项目初始化、目录组织、descriptor/replace_path、defines 策略、Git/CI/发布流程。
> 参考样本：Kaiserreich（KR）、Equestria at War（EAW，含开源 GitHub 仓库）。

## 一、目录组织（两者一致的标准做法）

```
mod根目录/
├── descriptor.mod        # mod 信息（name/path/supported_version/tags/replace_path/dependencies）
├── common/               # 全部机制定义（与游戏本体 common/ 同构，约 70+ 子系统目录）
├── events/               # 事件（add_namespace + country_event）
├── history/              # countries（开局国家）/ states（州）/ units（OOB）/ general
├── localisation/         # english/simp_chinese 等语言目录（*.yml，UTF-8 BOM）
├── map/                  # provinces.bmp / definition.csv / strategicregions/ 等
├── gfx/ interface/ portraits/ music/ sound/   # 美术与 UI
├── country_metadata/     # 国家元数据（KR/TNO 有）
└── tests/                # 脚本测试（KR 有）
```

- KR：`common/` 下 73 个子系统目录全量镜像本体；events 210 个文件、national_focus 197 个、decisions 256 个、scripted_effects 182 个、scripted_triggers 111 个、characters 228 个、units 371 个。
- EAW：结构相同，规模更大（history/states 1209 个、map/strategicregions 329 个、factions 101 个、on_actions 119 个）。

**规则**：mod 文件与本体同路径即覆盖本体；不同文件名的新文件与本体**合并加载**（同目录多文件叠加，按 ASCII 文件名排序，`00_` 前缀排前、`zz_` 前缀排后）。

## 二、descriptor.mod 与 replace_path

```
name="My Mod"
supported_version="1.19.*"
tags={ "Alternative History" "Map" }
picture="thumbnail.png"
path="C:/.../mod/MyMod"          # 注意：正斜杠；路径不能含非 ASCII 字符
replace_path="common/ideologies" # 整目录卸载原版，用本 mod 全部文件接管
replace_path="history/states"
dependencies={ "Main Mod" }      # 加载顺序（依赖 mod 先加载）
remote_file_id="12345"           # 仅工坊 mod
```

- KR 用了 77 条 replace_path（含 `common/*` 全部子系统、`events/`、`history/*`、`map/strategicregions`、`map/supplyareas`、`gfx/flags` 等）。
- EAW 用 50 条（无 `common/achievements`、`common/defines`——defines 用自命名新文件）。
- **replace_path 注意事项**：
  - 只对"按目录索引加载"的文件生效；`history/units`（通过 `oob = "TAG_xxx"` 直接链接加载）、`gfx/flags`（按需加载）对其无效；
  - 不改变加载顺序（改顺序用 `dependencies`）；
  - 被替换目录内至少保留一个有效内容文件，否则某些系统（如 national_focus）直接崩溃；
  - 同一目录内若同时有本 mod 与原版文件，仅当 replace_path 后才不会误读原版。
- **同名 mod 冲突**：启动器里同名 mod 只有先加载者生效；不要订阅自己的 mod。

## 三、defines 策略（两种范式）

| | KR | EAW |
|---|---|---|
| 文件 | `common/defines/KR_defines.lua` + `KR_embargo_defines.lua` | `common/defines/eaw_defines.lua` + `eaw_graphics.lua` + `eaw_career_profile.lua` |
| 哲学 | **几乎不碰引擎数值**（不改 NTechnology/NEconomy），只改：紧张度全系清零、禁运参数、AI 科研 XP 兑换、装备损耗 | **大胆魔改**（训练等级 10、特种部队下限 32、女性将领概率 0.5、船坞产线 10、工厂 25 即列强等） |

**做法**：新建自命名 lua 文件（如 `zz_txg_defines.lua`）只写要改的键，游戏按文件合并覆盖；**不要复制原版 00_defines.lua**。

### 1910 开局三件套（本 mod 必改）
```lua
NDefines.NGame.START_DATE = "1910.1.1.12"
NDefines.NGame.END_DATE = "1950.1.1.1"
NDefines.NDiplomacy.TENSION_TIME_SCALE_START_DATE = "1916.1.1.12" -- 紧张度缩放起点
```
参考：EAW 1007 开局（缩放起点 1012，大战后）；KR 只延长 END_DATE 到 1959（保留 1936 开局，紧张度全系清零用脚本驱动世界）。

## 四、EAW 开源仓库的工程化（可直接借鉴）

仓库：`github.com/EaW-Team/equestria_dev`（master，活跃）

- **GitHub Actions 三件套**：
  - `Build Release.yml`：release 发布时自动打包（ImageMagick 处理封面 → zip → 自写 Python `hoi4_checksum.py` 计算 HOI4 校验和 → 回写 release 说明 → 上传 Steam Workshop）。关键：维护一份 `hoi4-vanilla-facts`（原版文件事实库，`update-vanilla-facts.yml` 自动更新），供校验和计算与版本同步。
  - `Generate GitHub Pages.yml`：仓库文档站。
  - `update-vanilla-facts.yml`：随原版更新同步事实库。
- **仓库内开发专属目录**（不下发游戏）：`documentation/`（镜像 P社官方 API 文档供查用）、`scripts/`（Python 工具链：draw.io 国策设计图→PDX 代码转换器、议会 GUI 生成器、国策图标闪光生成器、命名列表→scripted_localisation 生成器、fileformatter、transfertechgen 等）、`scenario_tests/`。
- **许可证**：EAW 自定义 LICENSE——"仅允许 EAW 团队在 Steam 发布"。即开源可读，不可搬运。

**建议**：《天下与万邦》初期至少做：Git 仓库 + `.github` 下的 CWTools 校验（cwtools-action）或文本检查脚本；后续按 EAW 模式逐步加自动化打包。

## 五、关键工作流规范（社区共识）

1. **绝不直接修改游戏本体文件**（`E:\Steam\steamapps\common\Hearts of Iron IV`）——改动一律走 mod 目录；防止 Steam 校验还原。
2. **编码**：普通 `.txt` 用 UTF-8 **无 BOM**；本地化 `.yml` 用 UTF-8 **带 BOM**。BOM 也决定文件是否支持非 ASCII 字符（人物特质名、adjacency 规则等不支持非 ASCII）。
3. **路径**：mod 路径与游戏用户目录都不能含非 ASCII 字符，否则本地 mod 加载失败且错误日志打不开。mod 建议放 `D:/` 下纯 ASCII 路径，descriptor 用 `path = "D:/TxGMod"` 指向。
4. **减少覆盖**：优先新增独立文件（自命名，如 `zz_txg_xxx.txt`），只有必须整体重写时才同名覆盖；版本更新后用 WinMerge/KDiff3 合并。
5. **调试**：`-debug` 启动项（热加载 mod 文件、地图错误不崩溃、MAP_ERROR 才记录、主菜单 nudge、GUI 元素悬停查看）；日志在用户目录 `logs/error.log`。
6. **提交前核对**：`git status`/`git diff`，只提交有意的改动（见 AGENTS.md）。

## 六、EAW/KR 的国家文件"总装清单"写法

`history/countries/TAG - 国家名.txt` 是一个国家的全部开局配置集中地，固定顺序：
1. `capital = X`、`oob = "TAG_1936"`、`set_naval_oob`、`set_research_slots`、`set_stability`、`set_war_support`
2. `set_technology`（按 DLC 分支 if/else 写两套）
3. `complete_special_project` / `add_breakthrough_progress`（特种工程）
4. `set_politics` + `set_popularities`（意识形态分布）
5. 外交（`create_faction_from_template`、`set_autonomy`、`add_opinion_modifier`）
6. **机制变量初始化**（KR：国会席位 `GER_SPD_seats = 125`；EAW：邪恶计量器旗标）
7. `country_event = { id = xxx days = N }` 预排开局剧情时间轴
8. `recruit_character` 批量角色（`retire = yes` 管理初始不可用）
9. `add_ideas` 开局国家精神

本 mod 的大顺开局文件应完全按此模板组织。

## 七、RT56 扩展视角：追加式开发（与原版共存）

KR/EAW/KX 都是 replace_path 全接管式，RT56 提供**另一条路线**（见 [11-RT56追加式开发参考.md](11-RT56追加式开发参考.md)）：

- **descriptor 仅 3 条 replace_path**（history/states、map/strategicregions、gfx/fonts）——只接管引擎无法增量合并的资源，其余全部增量；
- **三管齐下**：新文件名追加（新国家/事件/国策/决策一律 `r56_` 前缀或新 TAG）→ 同名覆盖（必须改原版时，**保留原版事件 id 与 namespace**，新事件从高号段追加）→ 引擎替代（defines 用 `r56_defines.lua` 新文件、本地化用 `localisation/simp_chinese/replace/` 子目录、国策树用 game_rule + `load_focus_tree` 动态切换）；
- **23 国国策树动态切换**：`XX_focus_tree_selection` 游戏规则（默认 R56_TREE，`allow_achievements = yes`）→ on_startup 按规则+has_dlc 加载 RT56 树或原版 DLC 树，并双向清理对方专属内容（remove_ideas/remove_power_balance/retire_character）——**"本 mod 树 vs 原版树"剧本选项的官方解法**；
- 兼容细节：tag 冲突注释保留（`#SWK = ... #Now SAR to match vanilla`）、`NOT = { has_dlc = "Gotterdammerung" }` 让位、`has_global_flag = XXX_dlc_focus_tree` 让位、废弃文件整体注释。

**项目决策提示**：若《天下与万邦》做全替换（新地图/新开局 1910）走 KR/EAW 路线；若保留原版地图与机制（1936 延续型）走 RT56 路线。按当前世界观（1910 开局、全球重划），预计以 KR/EAW 全替换为主，RT56 的"动态国策树切换"与"共享国策聚合器"两个技巧仍可直接借鉴。
