# 《天下与万邦》多 agent 协作框架

> 适用：opencode（主力）+ subagent（长程自动化）+ codex（辅助）+ claude code（少量）跨三机异构协作。
> 本文档是三种 agent 的开工手册——开工第一步必读本文件 + `AGENTS.md` + `协作/任务台账.md`。

---

## 一、工具分工矩阵

| 工具 | 角色 | 触发 | 产出归档 |
| ---- | ---- | ---- | ---- |
| **opencode**（主力） | 主开发+调度大脑+长程自动化 | 常驻 | 直接写 mod 目录 + `协作/` |
| └ subagent·扫描（只读） | 一次性盘点原版 states + 设定卷审计 | 项目启动 1 次（仅全功能机） | `协作/扫描产出.md` |
| └ subagent·执行（按洲分治） | 东亚/北美/欧洲…写 mod 目录 | 阶段内 dispatch | mod 工程文件 + `协作/交接单/` |
| └ subagent·验证（阶段闸门） | 一致性+合规检查（清单 4 项） | 每洲完成时 | `协作/审查记录/验证-XX.md` |
| **codex**（辅助） | 框架搭建/扫描纠错/review/测试 | 阶段末手动启动 | `协作/审查记录/codex-*.md` |
| **claude code**（少量） | debug/bug 修复/review/方案设计 | 总装/验证期手动启动 | `协作/审查记录/cc-*.md` |

**调度模式（混合）**：opencode 内部长程自动化走 subagent（不打扰用户）；codex/claude code 由用户在关键阶段（骨架完成/归属表完成/总装完成）手动启动做 review/debug。

## 二、Memory 框架（协作层，三种 agent 共享）

三种工具互不共享会话上下文——共享记忆只能落在项目文件。结构：

```
协作/
├── README.md              # 框架说明+开工必读
├── 任务台账.md            # 任务状态机（见下）
├── 扫描产出.md            # subagent·扫描一次性产出（原版 state 清单+38 tag↔本世界归属锚点表）
├── 交接单/                # 每个执行 subagent 完成时写一份
│   └── 东亚-states映射.md
├── 审查记录/              # 验证 subagent + codex + claude code 的输出
│   ├── 验证-东亚.md
│   ├── codex-骨架review.md
│   └── cc-bug修复-总装.md
└── 会话记录/              # 长程 subagent/外部 agent 会话摘要（恢复用）
    └── 2026-08-05-opencode-东亚执行.md
```

### 任务台账字段（机器可读表格）

| 任务ID | 模块 | 状态 | 负责人（机+工具） | 分支 | 领取时间 | 最后心跳 | 交接点 | 产出文件 | 阻塞项 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |

- **状态**：待办 / 进行中 / 待验证 / 待测试 / 完成 / 阻塞
- `待测试`：验证通过但需加载测试（仅 full 机；light 机在台账标"待测试"→用户手动中继）
- **分支/领取时间/最后心跳**：支撑原子领取与过期锁恢复（见下）
- **交接点**：上一任务产出文件路径 + 下一任务入口
- 三种 agent 开工前必读此表，按**原子领取协议**领取/交接（见 `协作/README.md`）
- **并发软锁**：状态=进行中即独占该模块（一模块一机）；过期锁=24h 无心跳可被重置

### 原子领取协议（防多机双重领取）

1. `git pull --ff-only`（失败→停止）
2. 选状态=待办任务
3. 填：负责人=本机、分支=`<任务ID>-<机器ID>`、领取时间=现在、状态=进行中
4. **立即** `git add 协作/任务台账.md && git commit -m "lock <任务ID> @ <机器ID>" && git push`
5. push 被拒→他人已领，**不得执行**，重新 pull
6. 长程执行中每子步更新"最后心跳"并 commit+push

### 会话摘要格式（长程恢复用）

```
## 会话：[agent] - [任务] - [日期]
- 已完成：...
- 决策点：...（拍板结论）
- 遗留/阻塞：...
- 下一入口：读 协作/扫描产出.md + 设定书 XX 卷
```

## 三、Workflow（阶段+交接协议）

```
阶段A 工程骨架
  ├─ opencode 主进程：搭 mod 目录/descriptor/defines 三件套/书签/replace_path
  └─ 【手动】codex 扫描框架纠错 → 审查记录/codex-骨架review.md

阶段B-0 扫描（一次性，仅全功能机）
  └─ subagent·扫描（只读）：盘点本体 history/states + 设定书 08 卷归属锚点
     → 协作/扫描产出.md（38 tag↔原版state映射表骨架）→ 提交 git 共享

阶段B 执行（按洲分治，可并行/串行）
  ├─ subagent·执行-东亚：读扫描产出+11卷东亚节 → 写 history/states → 交接单
  ├─ subagent·执行-北美：...（最大工程；新瀛/美国1-2州等需用户界线拍板前置）
  ├─ subagent·执行-欧洲：...
  └─ 每洲完成 → subagent·验证跑清单 4 项 → 审查记录/验证-XX.md
                                    └─ 失败 → 回执行 subagent 修正（编排循环）

阶段C Nudge精调（省界级）+ 阶段D 国家总装
  ├─ opencode 主进程：country 文件 9 步（依赖领导人/意识形态/工厂换算——并行缺口工作包）
  └─ 【手动】claude code debug/review → 审查记录/cc-*.md

阶段E 验证（仅全功能机）
  └─ opencode 加载测试（仅全功能机）+ 【手动】codex 测试套件 → 审查记录汇总
```

**交接协议**：每个 subagent 启动第一步 = 读 `协作/README.md` + `AGENTS.md` + `协作/任务台账.md`（领任务）+ 对应设定卷；结束 = 写交接单/审查记录 + 更新任务台账 + （长程）写会话摘要。

## 四、subagent 配置（D 混合三角色，落地 `.opencode/agent/*.md`）

| subagent | 权限 | 读取 | 写入 |
| ---- | ---- | ---- | ---- |
| 扫描 | **限制写入**（edit deny *，仅 `协作/扫描产出.md` allow） | 本体 history/states（需 full 机 external_directory 授权）+ 设定书 | 仅 `协作/扫描产出.md` + 会话摘要 + 台账状态行 |
| 执行 | mod 目录写 + `协作/交接单/`写 | 扫描产出 + 设定卷 + AGENTS.md | mod 工程文件 + 交接单（不得写设定书/Settings/台账他人行） |
| 验证 | **限制写入**（edit deny *，仅 `协作/审查记录/验证-*.md` allow） | 执行产出 + 设定书 + AGENTS.md | 仅 `协作/审查记录/` |

> "只读"指限制写入范围，非全只读——扫描/验证都有唯一允许写的产出文件（permission 用 `edit: {"*": deny, "<允许路径>": allow}` 实现）。

## 五、验证 subagent 检查清单（A 钉死，4 项机器可判）

> 验证基于**交接单结构化表**（执行 subagent 必填）检查，而非从代码反推：

| 改动文件 | 改动内容 | 设定来源(卷条) | 是否新增设定 | 修订记录位置 |
| ---- | ---- | ---- | ---- | ---- |

1. **可溯源**：交接单每行"设定来源"列非空且指向设定书真实卷条（grep 验证引用存在）——空或虚假=不通过
2. **硬约束3 合规**：改动文件路径全部在 mod 目录内（`git diff --name-only` 比对，无本体路径）——触本体=不通过
3. **修订记录登记**：交接单"是否新增设定=是"的行，对应 `设定书/00-总览与索引.md` 修订记录有登记——未登记=不通过
4. **无擅自补全**：改动中"待定/待确认"标注保留（grep 扫描未被静默删除/填实）——标注被抹=不通过

## 六、多机异构（三机协作）

### 机器与能力（二分模型）

| 机器 | 系统 | 游戏本体 | 能力档 |
| ---- | ---- | ---- | ---- |
| 机器 A（全功能机） | Windows | 能部署 | **全功能**：执行+扫描+测试+长程自动化 |
| 机器 B（Windows） | Windows | 视情况 | 视本体有无：全功能 或 轻量 |
| 机器 C（Ubuntu） | Ubuntu | 必然无 | **轻量**：仅逐轮对话式开发+codex/claude code（不能长程自动化、不能测试） |

**二分能力闸门（+ 默认拒绝）**：
- 有本体（`game_path` 可达）→ 告知开发者：可长程自动化+可测试
- 无本体 / local.json 缺失 / game_path 不可达 → **默认 light**：封锁长程自动化+扫描+测试，仅逐轮对话式开发
- 不得未经用户显式确认把 light 升级为 full
- 能力判定与开工许可由 `/env-check` command 执行（所有 agent/subagent 开工前必跑）

### 扫描频率（A+B）

- **A. 轻量能力探测**（游戏路径在不在、哪台机、git 状态）——每次任务前跑，毫秒级，作为开工能力闸门自检
- **B. 重量原版 states 盘点**——项目级一次性，仅全功能机跑，产出提交 git 共享，其他机读不重扫

### 多机同步与中继

- **git 为唯一同步层**：所有机器 clone 同一仓库（mod 工程+`协作/`+设定书）
- **扫描产出共享**：机器 A 一次性扫描 → `协作/扫描产出.md` 提交 git → 其他机直接读
- **测试手动中继**：非全功能机需加载测试时，在任务台账标"待测试" → **用户手动到 A 跑一轮** → 结果回写 `协作/审查记录/`

### 机器特定路径拆分（AGENTS.md 重构）

AGENTS.md 硬编码的 `E:\Steam\steamapps\common\Hearts of Iron IV` 是机器特定路径——拆出：
- AGENTS.md 改为引用占位符（如"游戏本体路径见本机 `.opencode/local.json` 的 `game_path` 字段"）
- 新增 `.opencode/local.json`（**gitignore**，不入库）：

```json
{
  "machine_id": "A",
  "os": "windows",
  "game_path": "E:\\Steam\\steamapps\\common\\Hearts of Iron IV",
  "capabilities": ["exec", "scan", "test", "long_running"]
}
```

- Ubuntu 机 `game_path` = `null`，`capabilities` = `["exec_dialog_only"]`
- 三种 agent 启动时读本机 `.opencode/local.json` 确认能力档

### 并发软锁

- 任务台账"进行中"状态=该模块独占（一模块一机），避免多机并发改同一文件
- 协作层文件（如台账）若多机同时改→git 冲突，建议每机写独立交接单文件而非共写台账（台账仅主进程或独占机更新状态行）
